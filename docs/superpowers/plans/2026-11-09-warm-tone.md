# 노랑 톤 전환 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 사이트·메일·티켓·로고 파일·발권기를 빨강/니어블랙에서 노랑 톤(C안)으로 한 번에 바꾸고, 예매 홈에 빛·부드러운 모양·"어디 앉을래요?"를 넣는다.

**Architecture:** 색은 `app/globals.css` 토큰 교체가 중심이다. `accent-ink`·`danger` 토큰을 새로 만들고, 위험 표시 자리는 `danger`로 옮긴다. 홈은 컴포넌트 클래스만 바꾼다. 메일은 각 파일의 색 상수 `C`를 바꾼다. 로고는 생성 스크립트 상수를 바꾼 뒤 다시 굽는다. 네 갈래(Task 1~4)는 서로 다른 파일만 만지므로 같은 작업 트리에서 병렬로 진행한다.

**Tech Stack:** Next.js(이 저장소 버전, `node_modules/next/dist/docs/` 참고) + Tailwind v4 `@theme`, HTML 메일(table), Python fontTools, sharp

**Spec:** `docs/superpowers/specs/2026-11-09-warm-tone-design.md` (시안 원본 `docs/superpowers/specs/assets/2026-11-09-warm-tone-mockups/VibeRound2.dc.html` 의 C, `VibeDesktopC.dc.html`)

## Global Constraints

- 색 값은 spec의 표 그대로다: ground #0E0D0B, card #1A1916, ink #F4F1EA, sub #ABA69C, dim #938E84, mute #736E65, line #2C2A26, line-strong #3D3A34, line-bold #4D4942, seat #1B1A17, taken #2C2A26, raised #201F1B(#26262A 자리는 #27251F), accent #F2B544, accent-ink #1A1408, danger #E2674E.
- 노랑(accent)은 브랜드 포인트에만 쓴다. 대상은 고른 좌석, 내 좌석, 예매 바 선택 좌석 번호, 티켓 좌석·확정/변경 도장, "상영까지 N일", 로고 점, 관리자 "대기 N"·"승인 대기"다.
- danger는 위험 동작 버튼과 오류 알림·문구에만 쓴다.
- 노랑 바탕 위 글씨는 accent-ink다. 밝은 바탕(`bg-ink`) 위에는 accent 글씨를 쓰지 않는다.
- 색 점 + 넓은 자간 굵은 라벨은 금지다. 예외는 "스크린", 영수증 "입장권", 관리자 "관리" 세 곳이다.
- 영문 장식 텍스트는 넣지 않는다. 서정 문장도 덧붙이지 않는다. 문구 변경은 "어디 앉을래요?"와 "이번 상영작"뿐이다.
- 로고 모양, 포스터 크기, 좌석 모양(10/5px 등), 화면 구조·로직, DB는 바꾸지 않는다.
- 병렬 작업 중에는 `next build`/`npm run dev`를 돌리지 않는다(.next 충돌). 전체 빌드는 Task 5에서 한 번만 한다. 커밋은 각 Task가 자기 파일만 `git add` 경로를 지정해서 한다.

## Review Focus

- 위험 표시가 노랑으로 남는 경우: 확인창 "확인"(danger 모드), 예매 바 위험 버튼, 오류 토스트는 danger(#E2674E)여야 한다. Task 2·3에서 grep으로 확인한다.
- 노랑 위 흰 글씨: 선택 좌석, 그 밖의 `bg-accent` 자리는 accent-ink 글씨여야 한다(대비). Task 2에서 확인한다.
- 동의 철회 확인 버튼(`bg-ink` + accent): 노랑이면 읽을 수 없다. danger도 밝은 바탕 위라 대비가 약하므로 `text-ground`로 둔다. Task 3에서 확인한다.
- 메일 테스트가 옛 빨강을 기대하는 경우: 테스트는 새 accent를 기대하고, 출력에 `#E0443B`·`#0F0F10`·`#F2F2F0`가 없어야 한다. Task 4에서 확인한다.
- 파비콘 캐시: `public/icon*.png`·`apple-touch-icon.png`가 새 노란 점 버전으로 교체돼야 한다. 파일 바이트가 바뀌었는지 Task 1에서 확인한다.
