# 노랑 톤 전환 — 감성 되살리기 (2026-11-09)

## 왜 하나

1~4단계 브랜딩 리뉴얼(구기 로고, 니어블랙, 가는 선, 빨간 포인트) 뒤 사이트가 깔끔해졌지만 "감성이 죽었다"는 평가가 나왔다(운영자, 동아리 차장 모두). 영화대교는 사이트부터 상영까지 감성으로 운영하는 동아리다.

시안으로 요소를 하나씩 바꿔 보며 원인을 찾았다(시안 캔버스 https://claude.ai/artifact/5KE1q7AZSatxfsTSg3bzPQ 의 "감성 찾기" 페이지, 원본은 `assets/2026-11-09-warm-tone-mockups/`).

- 로고는 범인이 아니었다. 송명 가로 로고와 로고 크게 배치는 둘 다 별로였다. **구기 로고는 그대로 둔다.**
- 감성을 살린 것은 세 가지였다.
  - 따뜻한 **노란 톤**: 포인트 색만이 아니라 톤 전체를 바꾼다.
  - 위에서 번지는 **빛**
  - **부드러운 모양**
- 문구는 길고 서정적인 문장이 아니라 **짧게 툭 묻는 한마디**가 먹혔다("어디 앉을래요?").
- "진짜 영화관처럼 보이게"는 더 이상 목표가 아니다. 리뉴얼에서 남길 것은 **애매한 것들을 정리한 로직**(좌석 구역 지도, 고정 레이아웃 티켓, 팝업 하나씩 띄우기, 관리자 탭 구조 등)이다.

채택안은 **C안**이다. 폰 시안은 `VibeRound2.dc.html`의 C(노랑 톤·작은 포스터), PC 시안은 `VibeDesktopC.dc.html`이다.

## 목표 / 하지 않을 것 / 실패로 볼 것

- **목표:** 사이트·메일·티켓·로고 파일·발권기 화면을 한 번에 노랑 톤으로 바꾼다. 모든 곳의 빨강 #E0443B가 사라져야 한다.
- **하지 않을 것:**
  - 로고 글꼴·모양·배치 변경
  - 포스터 크기 변경(폰은 작은 포스터 유지)
  - 화면 구조·동작 로직 변경
  - DB 변경
  - 오프닝 영상(5단계, 별도)
- **실패로 볼 것:**
  - 아이보리·크림처럼 보이는 바탕. 바탕은 "아주 살짝 따뜻한 검정"이어야 한다.
  - AI 느낌 장식. 특히 **색 점 + 넓은 자간 굵은 라벨**("● 이 번 상 영")과 화면 전체를 덮는 그라데이션 칠
  - 영문 장식 텍스트

- 노랑은 브랜드 포인트 자리에 쓴다. 대상은 고른 좌석, 내 좌석 번호, **예매 바의 "선택한 좌석" 번호**(시안대로, 지금은 ink), 티켓 좌석 번호·확정 도장, "상영까지 N일", 로고 '화'의 ㅏ 점이다. 관리자 "승인 대기 N" 같은 주의 표시도 브랜드 포인트로 보고 노랑을 쓴다 *(내가 정한 것)*. 주 버튼은 지금처럼 글씨색(ink) 바탕에 바탕색 글씨다.
- **시안과 문서가 다를 때:** 색·빛·카드는 시안을 따르고, 좌석 모양(둥글기 10/5px 등)과 구조는 지금 코드를 따른다. PC 시안의 좌석 12/6px는 옛 시안을 복사한 값이라 따르지 않는다.
- `app/privacy/ConsentStatusCard.tsx`처럼 밝은 바탕(`bg-ink`) 위에 accent 글씨가 있는 곳은 노랑이면 읽을 수 없으므로 accent-ink나 바탕색 글씨로 바꾼다.
- 빨강 위 흰 글씨였던 곳(`SeatGrid.tsx` 선택 좌석 `text-white` 등)은 노랑 위 **accent-ink** 글씨로 바꾼다. 노랑 테두리 + 노랑 글씨 버튼(`PeopleTab.tsx` 차단 해제)은 그대로 둬도 대비가 충분하다.
- 위 표에 없는 하드코딩 색은 같은 원리로 따뜻하게 옮긴다. 회색은 R>G>B로 살짝 노랗게, 명도는 거의 같게 둔다. 대상 파일은 `app/print/page.tsx`, `SeatGrid.tsx`, `SeatLegend.tsx`, `app/page.tsx`, 관리자 `Toasts`·`SeatZoneEditor`·`MailTab`, `lib/promoHeadlineCanvas.ts`다.
- **위험 표시는 새 토큰 `danger` #E2674E**(노랑 톤에 맞춘 차분한 주홍빛 빨강)를 쓴다 *(2026-11-09 사용자 결정)*. 지금은 취소·삭제·오류도 브랜드와 같은 `accent`를 쓰므로, `accent`를 쓰는 곳을 하나씩 보고 나눈다.
  - **danger:** 위험한 동작 버튼(예매 취소, 확인창의 위험 버튼, 관리자 취소·차단·지우기), 오류 알림·오류 문구
  - **accent(노랑):** 그 밖의 좌석·확정·주의 표시
  - 알려진 위험 표시 자리: `app/page.tsx`(확인창 위험 버튼), `app/cancel/page.tsx`, 관리자 `ReservationsTab`·`LogTab`·`PeopleTab`, `Toasts.tsx`(오류 토스트), `PrivacyConsentGate`·`RequiredReviewModal`·`MovieReviews`·`MovieTab`(오류 문구). 이 목록 밖에도 있으면 같은 기준으로 나눈다.
  - 메일에서도 같은 기준이다. 취소 티켓의 상태 도장이 지금 회색이면 그대로 둔다.

## 빛 (예매 홈만)

- 화면 맨 위 가운데에 노란 원형 빛 번짐 하나를 둔다. 배경 그라데이션 칠이 아니라 위쪽에 고인 빛이다.
  - 폰: 지름 **580px**, 원 중심이 화면 위 가장자리 근처에 오게(top -270px)
  - PC: 지름 **1040px**, top -560px
  - 색: `radial-gradient(circle, rgba(242,181,68,0.34) 0%, rgba(242,181,68,0.13) 38%, rgba(242,181,68,0) 70%)`. PC는 0.30 / 0.11.
- 스크롤하면 같이 올라간다(고정 아님). 클릭을 막지 않는다(`pointer-events: none`).
- 좌석표의 스크린 선은 아래로 노란빛이 은은하게 번진다(`box-shadow: 0 6px 28px rgba(242,181,68,0.35)`).
- 관리자·발권기·팝업에는 빛을 넣지 않는다.

## 부드러운 모양

- **예매 홈 영화 정보:** 유리 카드 하나에 담는다. 바탕 `rgba(255,255,255,0.05)`, 테두리 `rgba(255,255,255,0.1)`, 그림자 `0 24px 48px -16px rgba(0,0,0,0.7)`이다.
  - 폰: 둥글기 16px, 안쪽 여백 16px
  - PC: 둥글기 20px, 안쪽 여백 32px, 그림자 `0 32px 64px -24px rgba(0,0,0,0.75)`
- **포스터:** 둥글기 10px(폰)·12px(PC), 그림자 `0 0 25px rgba(0,0,0,0.6)`
- **버튼:** 주 버튼·예매 바 버튼·구역 버튼은 둥글기 12px
- **폰 하단 고정 예매 바:** 바탕을 반투명(`rgba(25,24,21,0.92)`)으로 한다.
- **PC 예매 띠:** "선택한 좌석 + 예매하기"를 둥근 카드(16px, 바탕 `rgba(255,255,255,0.04)`, 테두리 0.08)에 담는다.
- **예매 홈 상단 바:** 아래 구분선을 없앤다(빛이 이어지게).
- **팝업(창):** 예매 정보 입력, 결제 대기, 이용 안내, 후기 등은 둥글기 16px로 맞춘다. 좌석 모양(위 둥근 의자형)은 지금 그대로다.
- **관리자:** 색 토큰만 바뀌고 모양은 그대로다. 관리자는 도구라서 정돈된 지금 모양을 유지한다. *(내가 정한 것)*

## 문구

- 예매 중인 좌석표 제목 "좌석 선택"을 **"어디 앉을래요?"**로 바꾼다. 지난 회차 열람의 "좌석 배치"는 그대로 둔다. 읽기 전용이라 질문이 어색하다. *(내가 정한 것)*
- 영화 정보 배지 "● 이번 상영"은 점과 넓은 자간을 빼고 보통 굵기의 **"이번 상영작"**으로 바꾼다. "지난 상영작"도 같은 모양으로 맞춘다.
- 같은 이유로 **색 점 + 넓은 자간 굵은 라벨**을 전부 찾아 평범하게 바꾼다. 관리자 "다음 상영"과 "이번 상영" 점 배지(`MovieTab.tsx`)가 여기에 해당한다.
  - 예외: 좌석표의 "스크린" 글자와 발권기 영수증 "입장권"은 극장 표기 관습이라 둔다. 관리자 상단의 작은 "관리" 표기도 둔다.
- 그 밖의 문구는 바꾸지 않는다. 서정적인 문장을 덧붙이지 않는다.

## 로고·아이콘 파일

- `scripts/brand/build_logo.py`의 `RED`를 노랑으로 바꾸고 `INK_DARK`를 #F4F1EA로 바꾼 뒤 `public/brand/*.svg`를 다시 만든다. 이름(`RED`)도 뜻에 맞게(`DOT` 등) 바꾼다.
  - 어두운 바탕용: 점 #F2B544
  - 밝은 바탕용(`*-light.svg`): 흰 바탕에서 노랑이 묻히므로 진한 호박색 **#B07A12**를 쓴다 *(내가 정한 것)*
  - 흑백(`*-mono.svg`, 발권기 영수증): 지금처럼 검정
- `scripts/brand/rasterize.mjs`로 `public/brand/png/` 전체(파비콘 "화" 포함)를 다시 굽는다.
- `scripts/brand/gen-mail-assets.mjs`의 `BG`·`CARD`를 새 바탕·카드색으로 바꾸고 `lib/brandMailAssets.ts`(메일 로고 PNG, 절취선 홈)를 다시 만든다.
- 파비콘·앱 아이콘이 `app/` 쪽에 따로 복사돼 있으면 같이 교체한다.

## 메일

- 대상은 `lib/ticketMailHtml.ts`(예매 확정·입금 대기·취소 티켓), `lib/promoMailHtml.ts`(홍보), `lib/restrictionMailHtml.ts`(예매 제한·해제), `lib/promoHeadlineCanvas.ts`(홍보 큰 날짜·제목 PNG의 글씨색)다. 색 상수를 위 표대로 바꾼다.
- 노랑 위에 글씨가 오면 accent-ink를 쓴다.
- 메일에는 빛 번짐을 넣지 않는다. 메일 앱들이 radial-gradient를 거의 지원하지 않는다.
- 부드러운 모양은 `border-radius`만 쓴다. Outlook에서 각지게 보이는 건 허용한다. 대상은 티켓 카드 바깥 모서리(절취선 홈 PNG와 어긋나지 않게)와 주 버튼("좌석 고르러 가기" 등)이다. 구체적인 둥글기는 만드는 사람이 화면 기준(카드 16·버튼 12)에 맞춘다.
- 테스트(`node --test lib/*.test.mjs`)의 색 기대값도 새 값으로 고친다.

## 만드는 방법 (사용자 요청: 병렬로 빠르게)

서로 겹치지 않게 세 갈래로 나눈다. 파일 단위로 나눠 충돌을 막는다.

1. **브랜드 파일:** build_logo → rasterize → gen-mail-assets. 메일 갈래가 쓸 `brandMailAssets.ts`를 만들므로 먼저 끝내거나, 메일 갈래가 이 파일만 마지막에 받는다.
2. **사이트:** `globals.css` 토큰, 예매 홈(빛·카드·문구·라벨), SeatGrid/Legend, 팝업 둥글기, 관리자 라벨, 발권기 화면
3. **메일:** 메일 HTML 세 종류 + promoHeadlineCanvas + 테스트

끝나면 전체 빌드와 테스트를 돌리고, 저장소 전체에서 `E0443B`·`#0F0F10`·`#F2F2F0`가 `docs/` 기록 외에 남지 않았는지 확인한다. 라이브 배포는 사용자 확인 뒤에 한다(DB 변경 없음, `npm run deploy`).
