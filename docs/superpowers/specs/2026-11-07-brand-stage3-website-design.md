작성일: 2026-11-07 · 선행: `2026-11-07-brand-identity-design.md`(1단계), `2026-11-07-brand-stage2-tickets-design.md`(2단계, 브랜치 `brand/stage2` c09d285)

시안: 캔버스 https://claude.ai/artifact/5KE1q7AZSatxfsTSg3bzPQ
- 페이지 "3단계 웹 — 폰·PC 좌석": `W3PhoneBlock`(폰·중강당), `W3PhoneGrand`(폰·대강당), `W3Desktop`(PC). `W3PhoneScroll`(가로 밀기)과 `W3ZoneIcons`(구역 버튼 비교)는 탈락안, 참고용.

캔버스를 못 여는 빌더를 위해 확정 시안 원본(`.dc.html`)을 `docs/superpowers/specs/assets/2026-11-07-stage3-mockups/`에 복사해 두었다. 브라우저로 열면 `support.js`가 없어 동적 부분은 안 그려지지만, 크기·색·간격 값은 소스에서 읽을 수 있다. **시안과 이 문서가 다르면 문서가 우선한다**(문서에 나중 결정이 반영돼 있음).

## 1. 왜

목표는 처음 보는 사람도 "진짜 영화관"으로 믿게 하는 것이다(1단계부터 같은 목표). 1·2단계에서 로고·색·티켓을 바꿨다. 웹사이트는 아직 옛 남색→주황 팔레트에 Song Myung "영화/대교" 두 줄 로고다.

관리자 화면은 사용자 말로 "관리자 할 때도 많이 힘들었어. 버튼들부터 겁나 비직관적… 이참에 갈아엎자". 관리자는 색만 바꾸지 않고 구조부터 다시 짠다. 사용자가 꼽은 관리 일은 영화 설정, 메일 보내기, 사람 권한 관리다.

배포는 사용자 결정대로 **1·2·3단계를 한 번에** 한다(3단계가 끝나야 배포).

## 2. 목표 · 비목표 · 반목표

**목표**
- 예매 홈(`app/page.tsx`)과 관리자(`app/admin/*`)에 1단계 브랜드를 입힌다.
- 폰과 PC를 둘 다 제대로 만든다. 예매하는 사람은 주로 폰, 관리자는 주로 PC(가끔 폰)다.
- 관리자를 "하는 일" 단위로 다시 짠다. 버튼은 한 번만 눌러도 되게 한다.

**비목표**
- 승인·취소·홍보 메일 템플릿(4단계), 오프닝 영상(5단계).
- 예매 규칙 자체(초대 명단, 후기 필수, 단체 예매, 결제 흐름). 동아리 전용 0석만 예외다(§6).
- 메일 발송 계정·방식.

**반목표** (기술적으로 돌아가도 이렇게 되면 실패)
- 아이보리·크림 바탕, 세리프 제목, 테라코타 포인트(사용자가 "너무 AI 같다"며 롤백한 적 있음).
- 로고·시각물에 영문명("MOVIE BRIDGE", "CINEMA CLUB" 등).
- 사물 모양을 그대로 그린 장식(다리 실루엣 등).
- 폰 좌석이 지금보다 작아지거나, 폰에서 좌석을 보려고 옆으로 밀어야 하는 것.
- 관리자 동작을 "⋯" 메뉴나 확인창 뒤에 숨기는 것.
- 무지개 색. 탭이나 구역마다 다른 색을 쓰는 것.

## 3. 브랜드 규칙 (1단계 확정, 다시 적음)

- 색: 바탕 `#0F0F10`, 카드 `#18181A`, 글씨 `#F2F2F0`, 보조 `#A1A1A6`·`#8E8E93`, 흐린 글씨 `#6E6E73`, 선 `#2A2A2E`(더 밝은 선 `#3A3A3F`·`#4A4A50`), 빨강 `#E0443B`.
- 빨강은 꼭 필요한 곳에만 쓴다. 로고의 '화' 점, 고른 좌석, "이번 상영" 점, 관리자의 승인 대기 숫자, 위험 동작(취소·차단) 글씨.
- 주된 버튼은 흰 바탕(`#F2F2F0`)에 검은 글씨, 모서리는 각지게. 보조 버튼은 테두리만.
- 정보는 "극장 프로그램"처럼 가는 선으로 나눈다. 표 첫 줄 위는 밝은 선, 나머지는 어두운 선.
- 로고는 `public/brand/logo-horizontal-dark.svg`(구기 글리프 윤곽)만 쓴다. 구기 글꼴은 로고에만 쓰고, 본문은 Noto Sans KR(이미 `app/layout.tsx`에 있음)이다.
- 아이콘은 지금처럼 lucide-react를 쓴다. 이모지는 쓰지 않는다.

## 4. 예매 홈 (`app/page.tsx`)

### 4.1 공통
- 상단 바: 왼쪽에 가로형 로고, 오른쪽에 "이용 안내"와 프로필 동그라미. 관리자에게는 "관리자"와 "발권기" 링크가 지금처럼 보인다.
- 영화 정보:
  - "● 이번 상영"(빨간 점) → 제목 → 포스터 + 정보표(일시 / 장소 / 관람 등급 / 예매 마감).
  - 지난 회차를 볼 때는 "이번 상영" 대신 "지난 상영작"이라고 쓰고, 빨간 점을 뺀다.
  - 지난 회차 이동은 "지난 상영작 ›" 글자 링크로 한다. 지금의 양옆 화살표 동그라미를 대신하고, 동작은 같다.
- 정보표에서 "마감"은 정보표의 한 줄이다. 지금의 빨간 사이렌 배지를 대신한다.
- 로딩·로그인 확인 화면: Song Myung 두 줄 대신 가로형 로고. 주황 빛 번짐은 뺀다.

### 4.2 좌석 (사용자 결정)
- **줄 글자(A~I, A~R)는 지운다.** 좌석 번호가 `B01`처럼 구역+번호라 줄 글자와 맞지 않아 "의미 없다"고 했다. PC·폰·지난 회차 보기 모두 해당한다.
- 좌석 칸 안에는 지금처럼 좌석 번호를 쓰고, 예매된 좌석에는 예매자 이름을 쓴다(지금 동작 유지).
- 좌석 모양:

| 상태 | 모양 |
|---|---|
| 빈 좌석 | `#1A1A1C` 바탕, 1px `#4A4A50` 테두리 |
| 고른 좌석 | 빨강 채움, 흰 글씨 |
| 예매됨 | `#2A2A2E` 채움, 흐린 글씨, 이름 |
| 동아리 전용 | 2px 흰 테두리 |
| 불편 좌석 | 1px 점선 테두리 |

- 좌석 윗모서리는 둥글고 아랫모서리는 덜 둥글다(의자 느낌, 지금과 같음).
- 범례는 **동아리 전용, 불편 좌석 두 개만** 둔다. 나머지는 보면 안다.
- 스크린은 가는 흰 막대와 넓은 자간의 "스크린"이다. 지금의 "SCREEN" 영문 글자는 지운다.
- 단체 예매 모드·결제 대기·단체 대기 좌석: 지금은 초록·하늘·노랑이다. 새 팔레트로 옮긴다. **(내 판단, 사용자 확인함: "괜찮은 것 같아")**
  - 단체 예매에서 리더(나)와 멤버 좌석은 고른 좌석처럼 빨강 계열로 보인다. 리더와 멤버 구분은 모양으로 한다(예: 리더 채움, 멤버 빨간 테두리).
  - 결제 대기와 단체 대기는 무채색 빗금이나 점선 같은 무늬로 예매됨과 구분한다.
  - 정확한 모양은 빌더가 정하되, 색상만으로 구분하지 않는다(이전에 아이콘 형태로 이중 표시해야 잘 보였던 경험이 있음).
- 예매 마감 표시: 지금의 기울어진 빨간 "예매가 마감되었습니다" 도장 대신 새 팔레트로. 모양은 빌더에게 맡긴다.

### 4.3 PC (시안 `W3Desktop`)
- 폭 1120px 안쪽. 포스터 260×372 + 오른쪽 정보표(2열). 아래에 흰 "좌석 선택하기" 버튼과 "남은 좌석 n석".
- 좌석은 **48×56px**(지금과 같은 크기)로 전체 배치를 한 번에 보여 준다. 중강당 통로 간격은 44px.
- 좌석 아래 가는 선 뒤에 "선택한 좌석 B31 · E열 · 오른쪽 구역"과 흰 "예매하기" 버튼.
  - "E열 · 오른쪽 구역" 같은 부가 설명을 넣을지는 빌더가 정한다. 줄 글자를 지웠으니 빼도 된다.
- 대강당 PC: 27칸이라 48px이면 화면보다 넓다. 대강당만 좌석을 줄이거나 가로 스크롤을 허용한다. 빌더가 1120px 안에 들어가는 쪽으로 정한다(예: 36×44).

### 4.4 폰 (시안 `W3PhoneBlock`, `W3PhoneGrand`)
- 상단 정보는 압축한다. 포스터 84×120 옆에 제목(24px)과 정보표 3줄(일시 / 장소·등급 / 마감). 사용자가 "세로로 너무 길면 별로"라고 했다.
- **좌석은 구역 하나씩 보여 준다. 옆으로 밀지 않는다.**
  - 중강당: 왼쪽·오른쪽 2구역(가운데 통로 기준).
  - 대강당: 앞(A~H)·뒤(I~R) × 왼쪽·가운데·오른쪽 = 6구역(H열 뒤 통로 기준).
- 구역 고르기: **극장 배치도 하나가 곧 버튼이다** (사용자가 '나'안을 고름).
  - 스크린 막대 아래에 구역 네모를 실제 위치대로 놓는다. 대강당은 앞줄과 뒷줄 사이를 살짝 띄워 통로를 표현한다.
  - 네모 안에는 "54석"처럼 남은 좌석 수만 쓴다. 지금 보는 구역은 흰색으로 채운다.
  - 글자 라벨("왼쪽/오른쪽")이나 작은 좌석 점, 따로 둔 탭은 쓰지 않는다(사용자가 복잡하다고 함).
- 좌석 크기: 중강당 46×46, 대강당 37×44(390px 폭 기준, 줄 글자를 지운 만큼 넓힘). 더 좁은 폰에서는 칸이 줄어들어도 터치 영역 36px 아래로는 내려가지 않게 한다.
- 처음 열 때 보여 줄 구역: 내 예매 좌석이 있으면 그 구역, 고른 좌석이 있으면 그 구역(로그인 후 복원 포함). 둘 다 없으면 첫 구역. **(내 판단)**
- 고른 좌석이 있는 구역 네모에 표시를 할지는 빌더가 정한다. 하더라도 요소를 늘리지 않는 쪽으로 한다(예: 남은 좌석 숫자 옆 작은 빨간 점).
- 화면 아래 **고정 바**: "선택한 좌석 B31" + 흰 "예매하기" 버튼. 좌석을 고르기 전에는 숨기거나 "좌석을 골라 주세요"로 둔다. 내 예매·자리 이동·단체 예매 상태에서도 이 바의 내용만 바뀐다. **(내 판단, 사용자 확인함)**
- **"남은 좌석 n석"과 구역 네모 숫자 = 보는 사람이 지금 고를 수 있는 좌석 수** (사용자 결정).
  - 예매 행이 있는 좌석(확정·결제 대기·단체 대기 모두)은 뺀다.
  - 불편 좌석은 예매할 수 있으니 센다.
  - 동아리 전용 좌석은 동아리원·관리자에게만 센다. 일반 학생과 로그인 전 방문자에게는 뺀다.
  - 그래서 보는 사람마다 숫자가 다를 수 있다.
  - 계산 위치(화면 vs 좌석 RPC)는 빌더가 정한다. 동아리원 여부는 지금 홈이 이미 아는 값(`clubMemberIds` 등)을 쓴다.
  - PC 상단 "남은 좌석 n석"도 같은 규칙이다.
- 지난 회차 보기도 같은 구역 방식(읽기 전용)이다. 지난 회차에는 남은 좌석 숫자를 쓰지 않는다. **(내 판단)**
- 지금 있는 "옆으로 밀어서 확인" 안내는 지운다.

### 4.5 나머지 화면 (같은 규칙으로 옷만 바꿈)
내 예매 정보(확정·결제 대기·QR·계좌), 팝콘 선택 창, 단체 예매 창들, 후기 창(`components/MovieReviews.tsx`, `RequiredReviewModal.tsx`), 개인정보 동의(`components/PrivacyConsentGate.tsx`), 이용 안내, 알림·확인 창이 대상이다. 메일 링크·동의 창으로 들어오는 별도 페이지 `app/group-confirm/page.tsx`, `app/cancel/page.tsx`, `app/privacy/page.tsx`도 포함한다(한 번에 배포하므로 옛 화면이 섞이지 않게). **(내 판단)** 동작과 문구는 그대로 두고, 색·버튼·선·글꼴만 §3 규칙으로 바꾼다. 주황·초록·하늘·노랑·장미색 버튼은 모두 흰 주버튼과 테두리 보조버튼으로 바꾼다.

## 5. 관리자 (`app/admin/*`)

### 5.1 뼈대 (시안 공통)
- 탭 대신 **왼쪽 메뉴**(폭 220): 로고 + "관리" → **예매 · 상영 · 메일 · 사람 · 기록**. 예매 옆에 빨간 "대기 n". 메뉴 아래에 "예매 화면 열기 ↗", "발권기 열기 ↗".
- 폰(`W3AdminPhone`): 왼쪽 메뉴 대신 화면 아래 메뉴 5칸. 표는 한 줄짜리 목록으로 바꾼다.
- 새로고침해도 보던 메뉴에 머문다(URL에 반영, 예: `?tab=people` 또는 하위 경로). 방식은 빌더가 정한다. **(내 판단)**
- 지금 맨 위의 "새로고침" 주황 버튼은 없앤다. 데이터는 동작 뒤에 다시 불러온다. 필요하면 조용한 새로고침 아이콘 하나를 둔다. **(내 판단)**
- 관리자 로그인·권한 없음 화면도 새 팔레트로 바꾼다.

### 5.2 한 번 누르기 규칙 (사용자 결정: "최대한 버튼은 1번만 눌러도 되게")
- 동작 버튼은 줄이나 화면에 바로 보인다. "⋯" 더보기 메뉴는 쓰지 않는다.
- 확인창을 띄우지 않는다. 되돌리기 어려운 동작은 **누르면 바로 실행되는 것처럼 보이고, 몇 초 동안 "되돌리기 · n"을 띄운다.**
  - 예매 취소: 줄이 "A07 오태윤 예매를 취소했어요. 취소 메일은 5초 뒤 나가요 · 되돌리기"로 바뀐다. 5초가 지나면 실제 `CANCEL_RESERVATION`을 호출한다(그때 메일도 나감).
  - 차단: 같은 방식. `ADD_BLACKLIST_BULK`는 예매를 지우고 취소·차단 메일을 보내므로, "사람 넣기 → 차단"으로 여러 명을 넣을 때도 똑같이 5초 되돌리기를 거친다. **(내 판단)**
  - 차단 풀기(`REMOVE_BLACKLIST`, 해제 메일 발송)는 바로 실행한다(해가 없고 다시 차단하면 됨). **(내 판단)**
  - 홍보 메일 "보내기": 5초 카운트다운 뒤 발송을 시작한다. 그 사이엔 멈출 수 있다.
  - 지연 실행 방식(클라이언트 타이머로 늦춰 보내기 vs 서버 예약)은 빌더가 정한다. 사용자에게는 "5초 안에 창을 닫으면 실행되지 않는다"는 한계를 알렸고 받아들였다.
- 쉽게 되돌릴 수 있는 동작(권한 켜고 끄기, 승인, 발권 되돌리기)은 그냥 바로 실행한다.
  - 승인은 메일이 나가지만 되돌리기 대상이 아니다. 실수로 눌렀으면 취소한다. **(내 판단)**
- 위험 동작은 빨간 글씨로 쓰고, 옆 버튼과 선 하나로 떨어뜨린다.
- 지금 `alert()`/`confirm()`으로 띄우는 성공·실패 알림은 화면 아래 짧은 알림(토스트)으로 바꾼다. 실패는 사라지지 않게 둔다. **(내 판단)**

## 6. DB 변경: 동아리 전용 0석

지금은 VIP 값이 비면 기본값(중강당 A~C열 5~10번, 대강당 A~C열 10~18번)이 잡혀 0석으로 만들 수 없다. 이 기본값은 두 곳에 있다.
- 클라이언트: `lib/seatGrid.ts` `computeVipSeats`
- DB: `supabase/migrations/0016_reservation_guards_and_schema_cleanup.sql`의 `is_vip_seat()`. 예매 가드 트리거와 RPC(0016, 0021)가 이 함수를 쓴다.

사용자 결정: 관리자가 "동아리 전용 좌석 두기"를 끄면 이번 회차 0석이어야 한다.

- `movie_settings`에 켜고 끄는 값(예: `vip_enabled boolean not null default true`)을 더하는 새 마이그레이션(0022)을 쓴다.
- `is_vip_seat()`가 꺼짐이면 false를 돌려주게 한다.
- `computeVipSeats`도 같은 값을 읽는다.
- `UPDATE_SETTINGS`·`START_NEW_MOVIE` 페이로드에 그 값을 더한다.
- 컬럼 이름과 방식은 빌더가 정한다. 단 SQL과 TS가 같은 규칙을 갖게 한다(메모: `seatGrid.ts`를 바꾸면 SQL도 바꿔야 한다).
- 동아리 전용은 계속 네모 한 칸으로 저장한다. 좌석별 칠하기로 바꾸지 않는다.
- 적용은 `supabase db push --linked`. **프론트 배포 순서를 지킨다.** 새 컬럼을 읽는 프론트가 먼저 나가면 컬럼이 없어 깨질 수 있다. 기본값 true인 컬럼을 먼저 db push하는 쪽이 안전하다. 빌더가 순서를 계획에 적는다.

## 8. 제약과 지뢰 (기존 버그 이력)
- **Next.js 버전이 학습 데이터와 다르다.** 코드를 쓰기 전에 `node_modules/next/dist/docs/`를 읽는다(`AGENTS.md`).
- 배포는 Cloudflare Worker 수동 deploy(`movie-bridge`, Seong381400 계정, `CLOUDFLARE_ACCOUNT_ID` 지정)다. 다른 세션과 deploy가 겹치면 `.next`가 꼬이니 `pgrep`으로 확인한다. 배포 직후 15~20초 기다린 뒤 검증한다. 라이브 확인은 퓨니코드 호스트로 한다. 커밋·푸시·배포는 사용자 확인 후에 한다.
- 예매 홈에 이미 고쳐 둔 경쟁 상태와 지뢰를 다시 깨지 말 것.
  - `fetchSeqRef`: anon→auth 이중 실행 순서.
  - anon 응답의 `user_id` undefined 오매칭 가드.
  - 로그인 리다이렉트 후 `sessionStorage` `pending_seat_selection` 복원.
  - 비로그인 좌석 클릭 시 즉시 구글 로그인.
  - 불편 좌석 클릭 시 경고.
  - 후기 필수 대상이면 후기 창 자동 오픈.
  - 개인정보 동의 게이트.
  - 좌석 현황은 RPC 직결(anon RLS 함정).
- 폰 구역 보기를 넣어도 좌석 계산은 `lib/seatGrid.ts`의 `computeSeatId`를 그대로 쓴다. 구역은 화면에서 거르기만 한다.
- Workers CPU 한도: SSR 부담을 늘리지 않는다(지금 정적 캐시 + 브라우저 RPC 구조 유지).
- 메일 HTML은 이번 범위가 아니다(2단계에서 끝남, 4단계 예정).

- 폰(390px 안팎)과 PC(1280px)에서 예매 홈과 관리자 모든 메뉴를 브라우저로 띄워 본다. 텍스트 세로 쪼개짐, 가로 스크롤, 겹침이 없어야 한다.
- 예매 흐름 직접 확인:
  - 비로그인 좌석 클릭 → 로그인 → 좌석 복원
  - 예매, 자리 이동, 취소
  - 단체 예매
  - 지난 회차 보기
  - 마감 상태
- 관리자 흐름 직접 확인:
  - 승인, 발권 되돌리기
  - 취소 + 되돌리기(메일이 안 나가는지)
  - 권한 켜고 끄기, 차단 + 되돌리기
  - 상영 저장, 동아리 전용 끄기
  - 새 회차 시작
  - 홍보 메일(테스트 수신자로)
- 동아리 전용을 끈 회차에서 DB 가드가 실제로 VIP 검사를 하지 않는지 확인한다. 예: 비동아리원이 A01 예매 성공.
- 기존 테스트(`node --test lib/ticketMailHtml.test.mjs` 등)와 빌드(`npm run build`)가 통과해야 한다.
